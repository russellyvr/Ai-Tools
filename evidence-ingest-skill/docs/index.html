evidence-ingest

Deterministic, LLM-free closed-corpus ingestion — folder in, locked RAG-ready corpus out, with a legal-grade chain of custody. Ships as an agent skill for Claude Code and GitHub Copilot CLI, and as a standalone Python CLI.

What it does

Point it at a folder of mixed documents — business records, an email export, a research collection, scanned paper — and it produces a published corpus folder containing a content-addressed evidence vault, verbatim extraction bundles, retrieval-ready text chunks, and a tamper-evident provenance record for every byte. The corpus is then filesystem-locked and can be re-verified from its own bytes at any time.

It was built to legal-evidence standards: the same run that ingests ordinary documents also produces a defensible chain of custody. You do not pay extra for provenance — it is the pipeline's native output.

Why deterministic and LLM-free

Every byte that becomes corpus is produced by code, never by a model. Agents may orchestrate runs and summarize reports (the control plane), but nothing a model writes can enter the work, output, or derived folders (the data plane).

  • Reproducibility is the proof. Every artifact re-derives from source bytes and checks hash-for-hash. A model in the data path would make the corpus unverifiable.
  • Zero hallucination surface. Extraction is stdlib and pure-Python parsing with recorded parse warnings; nothing in the pipeline can invent content.
  • Model-proof floor. Better agent models improve orchestration for free; the evidentiary path has zero model dependency and can never silently degrade as models change.

Supported input types

FormatsLane
.txt .md .csv Native text, verbatim. CSV shape recorded; formulas inert.
.html .htm Deterministic stdlib visible-text extraction. Scripts never executed, resources never fetched; excluded blocks counted as parse warnings.
.docx .xlsx Pure-Python read-only parsers. Formulas stay source text; macros and links never execute.
.doc .xls Preserved verbatim in the vault, marked needs_conversion for offline conversion and re-ingest.
.eml RFC 5322 verbatim headers plus typed recipients.
.pdf .png .jpg .jpeg .tif .bmp OCR lane (cloud or local, below), or preserved verbatim with --no-ocr and marked for a later pass. Oversized PDFs are split deterministically in-memory and OCR'd per slice.

Pipeline

selftest→ scan→ ocr→ extract→ chunk→ validate→ merge→ verify→ corpus

Each stage refuses to run without the previous stage's gate. Gate files are bound to a hash of the package source code: edit any code and every gate goes stale, forcing re-attestation from selftest. There is no skip flag. One-shot mode: run --input IN --output OUT --no-ocr.

Legal provenance — chain of custody

  • Hash-chained custody log (_custody.jsonl): every event appends to a tamper-evident sha256 chain — including network activity and the enabling of any policy exception.
  • Content-addressed vault: source bytes stored under their own sha256; never renamed, rewritten, or normalized.
  • Manifest + Merkle seal: the published corpus carries a full manifest and Merkle roots; verify re-derives all of it from bytes.
  • Drop-record accounting: every rejected or skipped input is recorded with a reason; validation reconciles the counts.
  • Immutability: the published corpus is filesystem-locked after merge; derived analytics (Parquet/DuckDB) are rebuildable caches, never the authority.

Security mechanisms

default-denyNetwork guard. A socket-layer allowlist installs before any other import. The pipeline can reach nothing unless a specific flagged exception admits one host — resolved once, IP-pinned, so mid-run DNS repinning cannot redirect evidence bytes.

fail-closedCode-tree-hash gates. selftest and validate write gate files keyed to the package source hash; later stages refuse without them; any code edit stales them all.

adversarialFive-agent red team. Every selftest runs bitrot (corruption), contortionist (schema/formula abuse), doppelganger (identity collisions, unicode twins), inkwell (content-poisoning canaries), and masquerade (provenance spoofing) — 40 traps and 18 controls through the real pipeline code against synthetic fixtures, never the live corpus.

re-derivableFive validation levels. Admission checks, byte integrity, structural re-validation, semantic reconciliation, and seal/release — ending in full manifest and Merkle re-derivation from source bytes.

never storedEphemeral credentials. Cloud OCR takes a short-lived bearer token via --token-file (0600, deleted on every exit path). The token is never logged; only its sha256 enters the custody record.

OCR mechanisms

Google Document AI (cloud — documented, audited exception)

The only permitted cloud egress, and only when two flags are set together. Enabling it writes a cloud_ocr_exception_enabled custody event recording the host, pinned IPs, processor path, token-file sha256, and operator acknowledgment. Sync-only :process with inline bytes — batch mode is refused because it would stage evidence in cloud storage. All identifiers below are placeholders; supply your own.

python -m evidence_ingest ocr --work W --google-docai --allow-cloud-ocr \
    --project your-gcp-project-id --processor <PROCESSOR_ID> --location us \
    --token-file "$TMPDIR/docai.token"

docai-run.sh wraps the whole lane: it mints the token via gcloud service-account impersonation, passes it by file, and deletes it on exit. It ships with empty tenant defaults and refuses to run until you supply your own project and service account.

Local loopback / enclave (air-gapped alternative)

python -m evidence_ingest ocr --work W --endpoint http://127.0.0.1:5000 --allow-loopback-ocr
# or fully offline:
python -m evidence_ingest ocr --work W --export DIR    # … OCR elsewhere …
python -m evidence_ingest ocr --work W --import DIR

No OCR

--no-ocr is always safe: text, tabular, and OOXML ingestion is complete and authoritative; PDFs and images are preserved verbatim and marked ocr_unavailable for a later pass.

Prerequisites

  • Python 3.11+ with a virtualenv inside tool/: pydantic>=2.5,<3 plus python-docx and openpyxl (the red-team gate builds OOXML fixtures).
  • Optional, for corpus-mode analytics and oversized-PDF splitting: pyarrow, duckdb, pandas, pypdf.
  • For the cloud OCR lane only: the Google Cloud CLI (gcloud) and your own Document AI project and processor.

Installation

# macOS / Linux — pick your CLI:
./install.sh --claude      # → ~/.claude/skills/evidence-ingest
./install.sh --copilot     # → ~/.copilot/skills/evidence-ingest

# Windows (PowerShell 7+):
pwsh -File .\install.ps1 -Claude     # add -WhatIf to preview
pwsh -File .\install.ps1 -Copilot

Installers run as the current user, make no network calls, download nothing, and never touch configuration — they copy the skill folder, backup-first. Smoke-test everything without OCR or network:

skill/evidence-ingest/tool/demo/run-demo.sh
