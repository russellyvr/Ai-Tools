route-tune

The self-tuning half of a deterministic model-routing deployment for GitHub Copilot CLI. A skill that measures real routing KPIs, applies at most one bounded, logged, reversible change per cycle, verifies it against the next cycle — and reverts itself on regression. Built to help anyone cut LLM token spend without sacrificing output quality, with every design decision traceable to a measurement.

What it does

The closed feedback loop: measure → diagnose → tune one step → verify next cycle → revert on regression.

Invoke as /route-tune (interactive review) or /route-tune go (apply the recommended bounded change autonomously). The skill runs the companion deployment's deterministic KPI analyzer, compares results to targets.json, maps any breach to exactly one corrective lever, applies it within hard limits, logs it, and checks its own previous change for regression before doing anything new. If routing is healthy, it reports "no change warranted" — re-running without new data changes nothing.

How it runs

You invoke it. It never invokes itself.

route-tune is a manually run skill. There is no daemon, no watcher and no timer — nothing happens until you type /route-tune in a Copilot CLI session. Even /route-tune go, which applies the recommended change without stopping to ask, only ever runs because a human started it.

The one piece worth automating is the analyzer: standard-library Python, LLM-free, read-only. It measures; it never tunes. Schedule it weekly so the KPI report is already fresh when you sit down to review.

# macOS / Linux — crontab -e, Mondays at 09:00
0 9 * * 1  python3 "$HOME/.copilot/routing/analyze_routing.py"
# Windows — PowerShell 7, weekly on Monday
$a = New-ScheduledTaskAction -Execute 'python' -Argument "`"$HOME\.copilot\routing\analyze_routing.py`""
$t = New-ScheduledTaskTrigger -Weekly -DaysOfWeek Monday -At 9am
Register-ScheduledTask -TaskName 'CopilotRoutingAnalyzer' -Action $a -Trigger $t

On macOS a launchd agent with a StartCalendarInterval runs the same one-line command if you prefer it to cron.

Then make the review itself the weekly habit: run /route-tune, read the KPI table and the single change it proposes, and decide. The measurement is automated; the judgement stays yours. When routing is healthy the answer is “no change warranted” and you are done in under a minute.

Hard limits on self-modification

A self-tuning agent is only trustworthy if its authority is bounded. These bounds are the skill's core design.

  • At most one pin change AND one rubric-wording refinement per cycle; pin moves are exactly one tier class and must stay inside pin_bounds from targets.json.
  • Untouchable: general-purpose and security-review pins (stay inherit), the frontier floor on high-stakes work, the high-stakes override, and every non-routing section of the user's configuration.
  • KPI targets belong to the user — the tuner may never move its own goalposts (only the analyzer window and tier name patterns may track a changing model list).
  • Append-only changelog: every change records date, KPI evidence, exact before/after, expected effect, and the revert condition. settings.json is backed up before any edit.
  • Verify-and-revert: next cycle, the previous change is marked VERIFIED if its KPI improved or held; on regression it is reverted exactly, marked REVERTED, and cannot be retried for 3 cycles.
  • Provenance discipline: user-directed or externally-synced changes are logged but exempt from the change budget and revert logic — the heuristic never blames a sync for a KPI move it didn't cause.

Prerequisites

route-tune is a tuner, not a standalone tool.

  • The companion model-routing deployment (separate package: analyzer analyze_routing.py, targets.json, the routing spec, sub-agent pins in settings.json, and the inline rubric). Install it first — route-tune measures and tunes that system.
  • GitHub Copilot CLI with custom-skill support (~/.copilot/skills/).
  • Python 3.9+ on PATH (the analyzer is standard-library only).
  • Recommended: a weekly scheduled analyzer run (Task Scheduler / launchd / cron) so the KPI report is always fresh — see How it runs. The skill itself stays manual.

All measurement is local: the analyzer reads only the CLI's own session store under ~/.copilot/. Nothing leaves the machine.

Installation

Scripted (recommended) or manual. Installers run as the current user, make no network calls, and never touch your configuration.

# macOS
./install.sh

# Windows (PowerShell 7+)
pwsh -File .\install.ps1          # add -WhatIf to preview

cp -r skill/route-tune ~/.copilot/skills/route-tune

Method & cost discipline

How this was built, and what it costs to run.

This skill exists to keep a token-saving deployment saving tokens without anyone having to babysit it — and to do that at effectively zero token cost itself. The entire measurement path is LLM-free: the analyzer is standard-library Python reading local session data, so a tuning cycle spends nothing to find out whether the last change helped. The one-change-per-cycle budget, the pin_bounds clamp, the append-only changelog and the verify-and-revert rule exist for the same reason — an autonomous tuner that drifts is worse than no tuner at all, because it degrades output quality while appearing to optimise.

The self-improvement protocol, its hard limits and the diagnosis map were deliberated across an AI council spanning three independent vendors, each answering independently before anonymised cross-review:

That pass is what produced the “cannot game its own metrics” property: a tuner scored against KPIs it is also allowed to redefine will always converge on flattering numbers, so KPI targets were made user-owned and untouchable. Claims here are grounded in primary documentation and published prior artifacts rather than model recall — the derivations follow.

Sources & derivation

Sound provenance is the point.

  • Primary source — original iterative engineering. route-tune is the self-improvement protocol of model-routing spec v3.x, added after two earlier generations failed measurably (v1 hardcoded model names and went stale; v2 advisory prose showed near-total non-compliance in the event logs). The bounded self-modification rules — one change per cycle, verify-and-revert, untouchable floors, user-owned targets — came out of a cross-machine peer review between two independent live deployments of the same spec. The full lineage, with the measurements that forced each change, ships in the companion package's instructions/model-routing.md.
  • Platform: GitHub Copilot CLI documentation (custom skills, custom instructions, sub-agent model/effort configuration).
  • Related prior artifacts (context, not derivation): FrugalGPT (arXiv:2305.05176) and RouteLLM (arXiv:2406.18665) route by learned difficulty prediction; this system routes by verifiability and dispatch surface, and its tuner is deliberately deterministic so it cannot game its own metrics.
